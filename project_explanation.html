1 What is GrocerCart?

GrocerCart is a Grocery Management System — a web application that allows an admin (your teacher) to manage an online grocery store. It is built using:

  • PHP — the programming language that runs on the server and generates web pages
  • Oracle XE 11g — the database that stores all data (customers, products, orders, etc.)
  • HTML + Tailwind CSS — the frontend design that you see in the browser
  • OCI8 — the PHP extension (plugin) that lets PHP communicate with Oracle
  • XAMPP / Apache — the web server that hosts the PHP files locally
💡 Simple Analogy Think of it like a restaurant: Oracle is the kitchen (stores all the data), PHP is the waiter (fetches data and prepares web pages), and your browser is the customer (sees the final result).

🔑 What is OCI8?

OCI8 (Oracle Call Interface 8) is a PHP extension — think of it as a translator between PHP and Oracle. Without it, PHP has no idea how to speak Oracle's language. In your XAMPP setup, it is already installed and enabled (we verified this earlier).

⚠️ Why not use MySQL's PDO? The original GreenCart project used MySQL with PDO (PHP Data Objects). Oracle requires a different connector: oci_connect(), oci_parse(), oci_execute() etc. These are the OCI8 functions. We replaced every MySQL/PDO call with OCI8 equivalents.

4 Database Layer — Oracle Tables, Sequences & Triggers

📐 Entity Relationship — How Tables Are Connected

Customers (customer_id PK) │ │ 1 customer can have many orders ▼ Orders (order_id PK, customer_id FK → Customers) │ │ 1 order can have many order line items ▼ Order_Details (order_detail_id PK, order_id FK → Orders, product_id FK → Products) │ Products (product_id PK, vendor_id FK → Vendors) │ │ 1 vendor can supply many products ▼ Vendors (vendor_id PK) Delivery (delivery_id PK, order_id FK → Orders) └── 1 order has 1 delivery record

🔢 What is a Sequence? (Oracle's Auto-Increment)

In MySQL you write INT AUTO_INCREMENT and the ID increases automatically. Oracle does NOT have AUTO_INCREMENT. Instead we use a Sequence.

A Sequence is like a counter that Oracle keeps. Every time you insert a new row, the counter gives the next number.

-- Create a sequence (counter starting at 1) CREATE SEQUENCE seq_customers START WITH 1 INCREMENT BY 1; -- Use the sequence to get the next ID SELECT seq_customers.NEXTVAL FROM DUAL; -- returns 1, then 2, then 3...

We created 6 sequences — one for each table: seq_customers seq_vendors seq_products seq_orders seq_order_details seq_delivery

⚡ What is a Trigger?

A Trigger is a block of code that Oracle automatically runs when something happens to a table (before/after insert, update, delete). You don't call it — Oracle fires it automatically.

Trigger NameWhen it FiresWhat it Does
trg_customers_biBEFORE INSERT on CustomersGets next ID from seq_customers sequence (auto-increment)
trg_vendors_biBEFORE INSERT on VendorsGets next ID from seq_vendors
trg_products_biBEFORE INSERT on ProductsGets next ID from seq_products
trg_orders_biBEFORE INSERT on OrdersGets next ID from seq_orders
trg_order_details_biBEFORE INSERT on Order_DetailsGets next ID from seq_order_details
trg_delivery_biBEFORE INSERT on DeliveryGets next ID from seq_delivery
trg_calc_subtotalBEFORE INSERT on Order_DetailsAutomatically calculates subtotal = price × quantity
trg_update_order_totalAFTER INSERT on Order_DetailsUpdates the order's total_amount by summing all subtotals
trg_loyalty_pointsAFTER UPDATE on OrdersAwards loyalty points to customer when order is delivered
trg_check_priceBEFORE INSERT/UPDATE on ProductsRejects insert if price is negative (data validation)
-- Example: trg_calc_subtotal fires before every Order_Detail insert CREATE OR REPLACE TRIGGER trg_calc_subtotal BEFORE INSERT ON Order_Details FOR EACH ROW -- runs for every row being inserted DECLARE v_price Products.price%TYPE; -- variable to hold the price BEGIN -- look up the price from Products table SELECT price INTO v_price FROM Products WHERE product_id = :NEW.product_id; -- automatically set subtotal = price × quantity :NEW.subtotal := v_price * :NEW.quantity; END; -- :NEW means "the row being inserted right now"

👁️ What is a View?

A View is a saved SQL query that acts like a virtual table. Instead of writing a complex JOIN every time, you just query the view.

-- Create a view (saved query) CREATE OR REPLACE VIEW CustomerOrderSummary AS SELECT c.customer_id, c.name, c.email, COUNT(o.order_id) AS orders_count, NVL(SUM(o.total_amount), 0) AS total_spent FROM Customers c LEFT JOIN Orders o ON c.customer_id = o.customer_id GROUP BY c.customer_id, c.name, c.email; -- Use it like a normal table SELECT * FROM CustomerOrderSummary ORDER BY total_spent DESC;

📦 What is a Stored Procedure?

A Stored Procedure is a named, reusable block of PL/SQL code stored inside Oracle. It can accept input parameters and return output parameters.

-- Procedure: given a product name, return vendor name and category CREATE OR REPLACE PROCEDURE get_product_details( p_product_name IN Products.name%TYPE, -- INPUT p_vendor_name OUT Vendors.vendor_name%TYPE, -- OUTPUT p_category OUT Products.category%TYPE -- OUTPUT ) AS BEGIN SELECT v.vendor_name, p.category INTO p_vendor_name, p_category FROM Products p LEFT JOIN Vendors v ON p.vendor_id = v.vendor_id WHERE p.name = p_product_name AND ROWNUM = 1; END;
5 The Core Engine — db.php (Database Connection)
🔌
db.php — The Foundation of the Entire Project
C:\xampp\htdocs\GrocerCart\db.php

This is the most important file. Every other PHP file starts with require_once 'db.php' — this loads the database connection and all helper functions before anything else runs. If you change the Oracle password, you only change it here.

Part 1 — Connection Constants

// These 3 lines define HOW to connect to Oracle define('OCI_USER', 'salehin_076923'); // Oracle username define('OCI_PASS', '2207045'); // Oracle password define('OCI_CONNSTR', 'localhost/XE'); // host/service_name
Why define() instead of variables? Constants (defined with define()) cannot be accidentally changed anywhere in the code. Variables could be overwritten. This makes credentials safer.

Part 2 — getOCI() — The Connection Function

function getOCI(): mixed { static $conn = null; // static = remembered between calls if ($conn === null) { // oci_connect() is the OCI8 function to open Oracle connection $conn = @oci_connect(OCI_USER, OCI_PASS, OCI_CONNSTR, 'AL32UTF8'); if (!$conn) { $e = oci_error(); die('Connection Failed: ' . $e['message']); } } return $conn; // returns the live connection resource }

Key point: static $conn means the connection is created only once per page load and reused. This avoids opening a new Oracle connection for every query (which would be slow).

Part 3 — ociQuery() — Run SELECT and Get Results

function ociQuery(string $sql, array $binds = []): array { $conn = getOCI(); // get the connection $stmt = oci_parse($conn, $sql); // prepare the SQL (check syntax) foreach ($binds as $key => $val) { oci_bind_by_name($stmt, $key, $binds[$key]); // safely bind variables } oci_execute($stmt, OCI_DEFAULT); // run the SQL $rows = []; while ($row = oci_fetch_assoc($stmt)) { // fetch each row $rows[] = array_change_key_case($row, CASE_LOWER); // lowercase column names } oci_free_statement($stmt); // free memory return $rows; // return array of rows }

Part 4 — ociExec() — Run INSERT / UPDATE / DELETE

function ociExec(string $sql, array $binds = []): bool { $conn = getOCI(); $stmt = oci_parse($conn, $sql); foreach ($binds as $key => $val) { oci_bind_by_name($stmt, $key, $binds[$key]); } $ok = oci_execute($stmt, OCI_NO_AUTO_COMMIT); // don't auto-commit yet if (!$ok) { throw new RuntimeException('OCI Error'); } oci_commit($conn); // ← COMMIT saves the change permanently oci_free_statement($stmt); return true; }
🔒 What is oci_bind_by_name()? Instead of directly putting user input into SQL (which could allow SQL Injection attacks), we use bind variables like :name, :email. Oracle treats these as data, never as code. This is the secure way to write database applications.

// If the form was submitted (user clicked Save): if ($_SERVER['REQUEST_METHOD'] === 'POST') { // Get values from the HTML form $name = $_POST['name']; $email = $_POST['email']; if (!empty($_POST['customer_id'])) { // Has an ID → EDIT existing customer (UPDATE) ociExec( 'UPDATE Customers SET name=:n, email=:e WHERE customer_id=:id', [':n' => $name, ':e' => $email, ':id' => $_POST['customer_id']] ); } else { // No ID → ADD new customer (INSERT) ociExec( 'INSERT INTO Customers (name, email) VALUES (:n, :e)', [':n' => $name, ':e' => $email] ); } // Redirect back to the list page after saving header('Location: customers_list.php'); exit; }

Orders uses Oracle's date functions. Oracle stores dates differently from MySQL — we use TO_DATE() to convert a string to an Oracle date, and TO_CHAR() to format it for display.

// Inserting a date into Oracle (from HTML date input) ociExec( "INSERT INTO Orders (customer_id, order_date, status) VALUES (:cid, TO_DATE(:dt,'YYYY-MM-DD'), :st)", [':cid' => $customer_id, ':dt' => '2026-06-20', ':st' => 'pending'] ); // Reading date from Oracle (formatted as readable string) ociQuery("SELECT TO_CHAR(order_date,'YYYY-MM-DD') AS order_date FROM Orders");
📋
Order Details — 3 Files (Trigger Auto-Calculates Subtotal)
order_details_list.php  |  order_details_form.php  |  order_details_delete.php

When you insert into Order_Details, you only provide the quantity. The Oracle trigger trg_calc_subtotal automatically looks up the price and calculates subtotal = price × quantity. Then trg_update_order_total updates the order's total automatically.

// We only insert order_id, product_id, quantity // Oracle triggers handle subtotal and order total automatically ociExec( 'INSERT INTO Order_Details (order_id, product_id, quantity) VALUES (:oid, :pid, :qty)', [':oid' => 1, ':pid' => 5, ':qty' => 3] ); // After this: subtotal = 3 × $4.00 = $12.00 (set by trigger) // And Order #1's total_amount is updated to include this (by trigger)
